# Principles with falsification boundaries

The [adversarial A–H review](../research/adversarial-synthesis-20260923.md)
retests these claims against newer native tooling, historical milestones and
full Icy function-byte accounting. Its sources supplement the original catalogs.

## Supported cross-project patterns

**CROSS-PROJECT PATTERN — compilation context can change the result of a
function whose body is unchanged.** Empires' GAME neighbors depend on inline
ASM selecting the whole-TU TASM route; Icy Tower's HTTP/scroller probes change
an unchanged target when predecessor definitions change. SimAnt's unit
composition also changes private selector/binding context, which is a distinct
object-level effect. The common claim is context sensitivity, not one shared
register-allocation mechanism. Sources: Empires `empires-route-context`, Icy
Tower compiler-context mechanism, SimAnt scaffolded-unit mechanism in the
[catalog](mechanisms.md) and their linked dossiers.

**CROSS-PROJECT PATTERN — body equality is weaker than a complete recovery
claim.** Empires MUSIC retained a relocation-order problem; SimAnt checks
semantic fixups and private contributions; Icy Tower separates body/layout
from CU/PE proof; Stunts requires object/binding and strict hybrid acceptance.
These are independent implemented distinctions. They do not define one shared
acceptance algorithm. Sources: all four proof mechanisms and
[proof models](proof-models.md).

**CROSS-PROJECT PATTERN — source variants can collapse to fewer effective
outputs.** SimAnt FloodNestB and ChangeDirectory, Stunts matched/batched
capsules, and Icy Tower draw probes each store this behavior. Empires' negation
probes also show repeated compiler canonicalization. Identity scope differs
(raw OMF versus normalized code/fixups/context); counts are not interchangeable.
Sources: project output-collapse records, Empires negation trajectory,
[negative catalog](negative-evidence.md).

**CROSS-PROJECT PATTERN — useful partial results need separate states.**
Historical source order in Icy Tower, exact isolated bodies in SimAnt, useful
research objects in Stunts, and compatible module groupings in Empires all
preserve information without granting broader closure. The common practice is
to state exactly what was established. Sources: project dossiers' proof and
trajectory sections.

## Generic methods justified by those observations

**GENERIC METHOD.** Freeze oracle, toolchain, source and TU context identities;
name the mismatch dimension before choosing a hypothesis. Measure effects on
candidate versus parent as well as candidate versus oracle. Retain exact
neighbors and contradicted hypotheses. Move from expression to ABI, lifetime,
TU, object binding, compiler pass or tool support when the current axis stops
separating outcomes. A batch is useful when hypotheses are independent; adaptive
sequencing is useful when the last result determines the next hypothesis.

These are research procedures, not guarantees of a monotonic compiler gradient
or successful reconstruction. See [experiment design](experiment-design.md).

## Generalizations actively rejected or narrowed

| Tempting generalization | Countercheck | Retained claim |
|---|---|---|
| Always swap declarations for register mismatches | SimAnt's documented extern pairs control commutative operand choice; Stunts' camera swap moves BP homes but leaves the six-byte gap; Icy predecessor effects persist after some type/order corrections | Several compilers have observed declaration/context sensitivity, with different mechanisms. Test the local prediction. |
| Exact body bytes identify the historical TU | Empires leaves byte-neutral extensions uncertain; SimAnt scaffolded units make no unique filename claim; Icy source-order promotion still leaves register mismatches | Compatibility and historical identity are different evidence strengths. |
| Sorting/normalizing relocations is safe | Empires strict proof requires the original order; SimAnt compares semantic fixups rather than simply deleting operands | Any normalization must name a lossless-for-purpose contract and retain the raw identity. |
| Better byte length/similarity means a better hypothesis | Stunts camera stays short after better anchors; SimAnt ChangeDirectory's improved interpretation still fails bytes/fixups; Icy draw variants can lose neighbors | Track mismatch dimensions and tradeoffs, not one score. |
| No cheap-worker solve means the model is exhausted | Stunts omitted profiles/parser boundaries and early stopped runs; Empires two-fix retry gate is operational | Label budget/tool/evidence stops separately from search convergence. |
| Cheap and strong models have equal capability | Four selected Stunts pairs, two known-solvable replays, no new recovery and no Astra-only success | A local routing decision and scenario costs, not a population claim. |
| Batching improves recovery throughput | One Stunts pair saved direct cost/time but found fewer identities and zero strict matches | Batching can reduce overhead for suitable independent tests; throughput benefit is unproven. |
| Persistent compiler services are always best | SimAnt benchmark is strong locally; other projects use different runners/process costs and lack matched measurement | An adapter-specific engineering option requiring parity/isolation tests. |
| GCC peephole/pass behavior explains MSC/Turbo C | No independent supporting mechanism in those toolchains | Keep GCC4.4.1 diagnoses local. |

The audit explicitly treats absent evidence as unknown, not contradiction.
Tool deduplication received the same scrutiny: Stunts coordinates are generic
in concept but the existing script needs an adapter; the normalized catalog
corrects the broader worker classification. No historical runner/parser/gate
was extracted merely because it is Python.

## Working hypotheses for the next pass

**WORKING HYPOTHESIS.** Context-aware outcome matrices could reduce repeated
low-information retries across the active projects. The included utility makes
that hypothesis testable; its existence is not evidence of a measured speedup.

**WORKING HYPOTHESIS.** Strong models may be most economical on systemic
mechanism/tool discovery while cheaper workers explore bounded verified
hypotheses. Stunts motivates measuring this, but the present small cohort cannot
establish the optimal routing policy. A useful next test measures all worker,
supervisor and review overhead against effective new outcomes and strict solves.

The [fleet falsification review](../research/fleet/evaluation.md) retains this
as a **bounded Luna-first trial**, not a cross-project model-performance pattern.
The matched Stunts cohort shows a 1.32x hypothesis-effort ratio and a 64.17x
direct scenario-cost ratio, but equal outcomes on only four selected pairs,
zero new production recovery and no Sol comparison. Supervisor cost exceeded
combined worker cost. Neither a fixed 10x escalation threshold nor a large
unattended fleet is validated.

**GENERIC METHOD — escalate a mechanism question, preserve task ownership.**
Prefer compatible recurring blocker evidence or one high-impact systemic
question to an arbitrary failed-attempt count. Search convergence, budget,
tooling, evidence and production blocks have different meanings. Native
promotion remains serialized where required. SimAnt's compile locks do not
claim a job across model reasoning intervals; autonomous consumption needs
separate ownership and input-isolation guarantees.

**GENERIC METHOD — return validated discoveries to workers.** Encode supported
mechanisms as scoped diagnostics, generators, rules, context fields or tools,
with controls and counterexamples. Existing project tools demonstrate this
lifecycle; their authors' model identities are mostly unavailable. Strong-model
discovery amortization is a useful policy, not measured model superiority.
See [fleet operation](fleet-operation.md) for routing, recovery and reporting.

## Additional boundaries established by the adversarial review

**GENERIC METHOD — separate residue from cause.** A blocker describes the
candidate/context/evidence/tool/proof state. Preserve observed residue, supported
and rejected mechanisms, unresolved dimensions and capability/workflow blocks
separately. SimAnt's fresh labels change without proving semantic causes;
Stunts has overlapping categories and already implements transferred diagnostics.
Do not convert repeated symptoms into one causal explanation.

**GENERIC METHOD — choose the next scope from evidence.** Source regions can be
useful research units while compilation and acceptance cover the enclosing
function/TU. Data, fixups, profiles and protected peers form cross-cutting
dependencies; a universal escalation tree loses information. Use the
[scope graph guidance](recovery-levels.md) only where it reduces confusion.

**WORKING HYPOTHESIS — independently grindable regions.** Icy has region authoring,
machine chunks and line budgets, but semantic dependencies, peer regressions and
stale sidecars contradict unconditional independence. The
[region influence experiment](large-function-regions.md) must precede concurrent
region ownership. Region exactness never grants function acceptance.

**REJECTED / TOO STRONG:** a smooth compiler gradient, one permanent causal
blocker per function, throughput-based historical model ranking, or Empires'
convergence as proof that its entire post-bootstrap problem was easy. Retain
scoped response maps, stage/seed confounders and the separation between artifact
equality and natural source/topology closure instead.
