# Local requirements evidenced by the four reconstruction projects

**Read-only extraction, 2026-09-23.** These are **PROJECT FACTS** in their
named compiler, evidence, and acceptance contexts, except where explicitly
marked as a method or hypothesis.  They are requirements for evaluating an
external matching tool, not claims that every compiler has the same cause.
The source manifest in `local-requirements.json` pins the inspected live files
by SHA-256 and preserves Empires at its frozen commit.

## SimAnt: cheap search needs effective-output stopping and strict membership proof

SimAnt is 16-bit Windows/x86 reconstruction with authentic MSC 7.00, OMF/NE
member evidence, and its assigned `/AL /G2 /Gs /Oeglw /NT…_MODULE` component
profiles.  Its `_PlacePillTile` probe is a direct requirement for an experiment
runner.  Four bounded, isolated batches tried 24 variants: declaration and
assignment order, `register` locals, array representation/index spelling, and
prototyped versus K&R callee declarations.  They collapsed to **three effective
object hashes**.  All retained the 40-byte extent and two semantic bindings,
yet none reproduced the DI/SI argument-load and push schedule.  Therefore a
source matrix needs to group outputs by a context-bound object identity and
change the causal question after collapse; source count alone is not progress.
This is negative evidence for the listed representations and MSC 7 profile,
not a rule about `register` or C declarations generally.

The project also demonstrates that a bounded sequence can reach an exact
result.  `_MagnifyMenu` already matched 156 opcodes and 46 fixups, with four
literal differences involving the stack operand chosen for rectangle-bound
calculations.  Several expression forms collapsed; making a field volatile
regressed.  One final controlled local-order change (`screen, object, point`
to `screen, point, object`) selected the required operand schedule and passed
fresh exact member admission.  This is stronger than a function-body match:
the promotion's context includes the assigned compiler profile, member extent,
literal bytes, and fixups.  The shared layer should thus retain candidate
source, compiler fingerprint, raw/effective object identities, delta, and
strict verdict; it must never substitute a scalar similarity score for the
owning OMF/NE proof.

## Stunts: compiler work is inexpensive here, but policy efficiency is unproven

Stunts is DOS 16-bit medium-model MSC recovery with OMF/binding and hybrid
whole-image acceptance.  Its matched Luna/high and Astra/high pilot records
44 hypotheses, 40 identity-bearing results, and **24** profile-bound effective
identities after within-case/cross-model deduplication.  Ten occurrences repeat
an already-seen result in the same run.  Two selected replay cases attained
strict receipts in both arms; neither unresolved case did.  No Astra-only
solve, no new production C, and only four selected functions means this is not
a model-capability ranking.

The 50 recorded compiler processes consumed about **25.1 seconds** of trial
time while the eight model launches consumed about **2,342 seconds**.  That is
an observational cost signal: in this cohort, compiler experiments were cheap
compared with agent/supervisor interaction.  It is not a throughput estimate,
because the runs were not randomized batching conditions and preparation,
review, cache, and supervision were separate.

A newer controlled `unknown_libname_1` pair narrows the batching lesson.  Two
fresh Luna/high contexts shared target, seed, evidence, tool recipe and caps.
The adaptive lane ran 4 candidates/4 outputs; the preregistered batch ran
3/2.  Batch used 23% fewer requests, 9% less worker wall time, and 15% less
direct model-equivalent cost, but found half as many effective outputs and no
strict match in either arm.  It supports small predeclared batches of
independent hypotheses plus output deduplication, not a universal batch size
or a recovery-rate gain.  The remaining question was a compiler allocation/
ABI mechanism, so more surface source rewrites would be low-information.

## Icy Tower: source recovery sometimes has to escalate above a function

Icy Tower uses locked TDM GCC 4.4.1/i386, COFF/PE evidence and DWARF.  A
lexical-scope correction shows why language evidence is useful: DWARF placed
`localFilename[256]` as a function static rather than file static.  Moving the
unchanged declaration into that function preserved text, allocated contents,
static-symbol identities, common allocations and non-debug relocations; the
resolver proved BSS ownership and four references became exact.  A superficially
similar `face` move reordered BSS and changed operands, so a preservation gate
rejected and restored it.  Scope/type candidates must be tested against peers,
data and relocations, not only a target function's assembly.

The compiler-context probes establish a distinct escalation class.  In an
isolated full-CU copy, replacing the earlier `destroyHTTPResponse` definition
with a declaration changed two scratch-push differences in unchanged
`HTTPFetchInternal`; related omitted-peer/type tests did not repair it.
`draw_scroller` likewise changed when a predecessor was omitted, while six
target differences remained.  DWARF source order restored natural offsets and
a 640-byte text contribution but did not solve those six differences.  These
are observed dependencies, compatible with the documented GCC peephole
mechanism, not proof that every register mismatch is peephole state.

Finally, a `play` source split initially preserved seven `new_rand` calls
through optimized GIMPLE and RTL `179r.dse2`; at `181r.csa` one call disappeared
and a destination-label use changed.  The result remains `DIFFER`.  This gives
the shared workflow a concrete rule: when controlled source variants converge,
retain pass/TU/CFG evidence and move to a predecessor, lifetime, or dataflow
hypothesis instead of retrying equivalent spelling.  Icy's proof ladder keeps
FUNCTION, OBJECT, CU, layout and whole-image claims separate.

## Empires: full reconstruction needs link topology and historical TU routing

Empires' authority is the frozen Turbo C 2.0/TASM 1.0/TLINK 2.0 closure at
commit `873d1df…`.  Its receipt records a byte-identical executable hash, 106
ordered relocations, one linker invocation, zero raw-EXE fallback bytes, zero
unresolved symbols, and all 37,250 BSS bytes partitioned.  This is why an
instruction match cannot be the shared system's final acceptance condition.

The MUSIC trajectory is a direct relocation-topology requirement.  A TASM
construction could match arithmetic/body evidence but emitted ascending
FIXUPPs; the historical relocation order was descending.  The final single
pure Turbo C `MUSIC.C` unit reproduces 700 bytes, four public offsets and the
historical order through Turbo C's native object writer, then passes whole
acceptance.  A matching tool therefore needs to preserve raw relocation order
and distinguish a body result from a plausible compiler route.

TU routing is likewise evidence, not an optional build setting.  Turbo C's
inline `asm` causes the **whole C file** to restart through the assembler
(`-B`).  In GAME.C, `BOOTSEED`'s `asm sti` accounts for `-B`-dependent neighbors
such as TURNLOOP and LVLDRV; replacing it with an intrinsic breaks them.
`-B`-intolerant modules and DATA/relocation continuity bound the unit.  This
requires the eventual search state to name TU membership, declaration view,
compiler route and link checks when local function search stops separating.

## Resulting shared-tool contract

**GENERIC METHOD.** The reusable boundary is an adapter-neutral experiment
record, not a universal compiler runner: frozen oracle/compiler/context identity;
source hypothesis and prediction; candidate-versus-parent-versus-oracle deltas;
effective-output grouping; strict proof status; preserved negatives; and an
explicit escalation reason.  It should accept compact instruction feedback for
an AI agent, while adapters retain OMF/NE fixups, COFF/DWARF/layout, or
MZ/TLINK proof.  The four projects jointly justify a small independent batch
only when hypotheses do not require earlier output, then escalation to ABI,
lexical scope, predecessor/TU, compiler pass, object binding or linker topology
when effective outputs cease to add information.
