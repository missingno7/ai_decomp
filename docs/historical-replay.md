## Freeze evidence without making reconstruction impossible

First conduct a cheap feasibility audit: inventory every permitted source,
compiler/SDK/runner hash, original oracle, cached receipt and tool dependency.
Test baseline reproducibility only in the owning project's authorized isolated
trial. Missing historical untracked files are an evidence-retention limitation;
do not quietly replace them with later solutions. Report reproducibility failure
separately from worker failure.

A detached worktree still exposes future Git objects through the shared object
store. Use a sanitized exported tree or a history-limited store with an explicit
allowlist, no shared build/evidence directories and no later notes or branch
access. Restrict network access to prevent fetching future project solutions.
Historical tools can be supplied through a separately hashed, approved input
set. Retain a file-access manifest where practical.

The worker needs original binary/object/debug evidence to reason about recovery.
Do not hide the oracle from research. Instead, separate permitted evidence
inspection, declared source construction and independent acceptance. Preserve
the snapshot's baseline construction inputs, including documented Empires
adapters and synthetic ownership debt. Forbid new oracle-derived byte patches,
undeclared output reuse and changing the proof gate to accept the candidate.
The inherited debt is precisely what the closure trial must reduce.

## Comparison design

Choose a small frozen cohort before inspecting future successes. Include failures
and evidence/tool blocks, not only known-solvable cases. Give each arm identical
snapshot, objective, proof requirements, permitted tools and model-side budget.
Allow new tools, but log their implementation/review cost and validate their
independent output. Keep prompt/harness policy fixed when testing models.

To test stage rather than merely model rank, use a separate paired condition:
the same model/harness at the frozen stage versus the same frozen candidates
with explicitly supplied, validated diagnostic capabilities. Do not import later
candidate source or label this a pure stage effect; this condition estimates
the value of the specified tooling/evidence intervention. Early-versus-current
task populations require a stratified design because their difficulty differs.

Use independent replicas only where the additional variance estimate is worth
the budget. Record provider/model/effort, prompts, worker lineage, cache buckets,
tokens and total weighted model cost, including preparation, supervision and
review. Report compiler processes, output classes and informative interventions;
wall time is host-specific context. Run both equal-budget outcome and censored
time-to-result analyses rather than granting one arm unlimited search.

Score at least two outcomes independently:

1. **New strict recovery:** named contributions/bytes and protected-state debt,
   with native proof scopes. Inherited exact output earns zero new credit.
2. **Validated mechanism capability:** a diagnostic/generator/tool with positive
   and negative controls, then an assessor-selected held-out case from the same
   frozen evidence population. Count measured fan-out, not predicted unlocks.

Blind review of receipts should classify budget censoring, tool/evidence blocks,
current-level convergence and native rejection separately. A worker's mechanism
story is not proof. Use future history only after scoring to explain differences.
These proposals authorize no expensive model trial, fleet launch or sibling
production change; those are separate experiments after feasibility is established.
